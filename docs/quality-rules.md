# Data Quality Rules

## Categorisation

The selected category should represent the underlying service/technology issue closely enough to support:

- routing
- trend analysis
- problem management
- reporting
- service ownership

Generic categories should be the exception rather than the default.

## Priority

Priority should follow the agreed impact/urgency model. Analysts should not silently use priority as a proxy for personal judgement or customer seniority.

## Ownership

Resolver assignment should be consistent enough to understand demand and accountability.

## Completeness

Mandatory operational fields should be completed before closure where the process requires them.

## Quality principle

Data quality is operational control, not administrative tidiness. Poor data changes decisions.
